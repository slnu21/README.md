# README.md v0.7.1

가볍고 100% 오프라인인 마크다운 리더 & 에디터. Windows x64.

**미리보기에서 링크를 눌러도 아무 일이 없던 문제**를 고친 릴리스입니다.

## 수정

### 링크를 눌러도 아무 일이 없던 문제
- 미리보기에서 웹 주소(`http`/`https`) 링크를 눌러도 브라우저가 뜨지 않았습니다. 이제 **한 번 클릭하면 기본 브라우저로 열립니다**(`mailto:`·`tel:`도 같습니다).
- v0.6.8에서 넣은 외부 링크 처리가 앱 내부 권한 설정에 막혀 **처음부터 한 번도 동작한 적이 없었습니다.** 게다가 그 실패가 조용히 삼켜져 화면에도 로그에도 아무것도 남지 않았습니다 — 그래서 두 번의 릴리스를 버텼습니다. 이제 실패는 반드시 화면에 남습니다.

### 프레젠테이션에서 링크를 누르면 슬라이드가 사라지던 문제
- v0.6.8에서 미리보기에 대해서만 고쳐, 발표 화면에는 같은 증상이 그대로 남아 있었습니다.

### 그 밖에
- **눌러도 반응이 없던 링크가 왜 그런지 알려 줍니다** — 안전을 위해 막아 둔 주소(`javascript:` 등)나 앱 전용 주소(`obsidian:` 등)는 파랗게 밑줄만 그어진 채 아무 일도 일어나지 않았습니다.
- **`file:///` 링크가 열립니다** — 로컬 파일을 가리키는 링크로 보고 다른 로컬 링크와 똑같이 다룹니다. 문서에 HTML로 적은 링크에 해당합니다 — 마크다운 `[글](file:///…)` 문법은 원래부터 링크가 만들어지지 않고 글자로만 남습니다(`javascript:`도 마찬가지).
- **모르는 주소 형식이 엉뚱한 경로로 해석되던 것** — `ftp:`·`obsidian:` 같은 것을 문서 폴더 아래 파일로 착각해 열려고 하던 경로를 끊었습니다.
- **배지 이미지가 링크로 갑니다** — README에 흔한 `[![배지](이미지)](주소)`가 확대만 되고 링크로 이동하지 않던 것을 고쳤습니다. 링크로 감싸지 않은 이미지는 그대로 확대됩니다.

## 새 기능

### 링크 수식어
| 대상 | 클릭 | Ctrl(⌘)+클릭 | Alt+클릭 |
|---|---|---|---|
| 웹 주소 · `mailto:` · `tel:` | 기본 브라우저 | (같음) | (같음) |
| 문서 안 `#앵커` | 문서 내 스크롤 | (같음) | (같음) |
| 다른 `.md`·`.txt` | 현재 자리에서 열기 | **옆 패널에 열기** | **탐색기에서 위치** |
| `.pdf`·이미지 등 | OS 기본 앱 | (같음) | **탐색기에서 위치** |

- 미리보기는 읽는 면이라 **그냥 클릭이 곧 열기**입니다. `Ctrl`을 눌러야 열리는 방식은 쓰지 않았습니다.
- `Ctrl`+클릭은 v0.7.0의 리딩 모드 좌우 분할로 이어집니다(탭 우클릭 "옆에 나란히 열기"와 같은 동작).

- 못 여는 링크·없는 파일·안전상 열지 않는 형식을 화면 아래에 알려 줍니다.
- 링크에 마우스를 올리면 어디로 가는지 보여 줍니다.

## 안전
- **문서 안의 링크로는 실행 파일이 열리지 않습니다.** 로컬 파일 링크는 앱 뒤쪽(Rust)에서 확장자를 검사합니다. 실행·스크립트(`exe`·`bat`·`ps1`·`msi`…), 바로가기류(`lnk`·`url`·`hta`·`chm`), 그리고 **로컬 HTML**은 열지 않고 대신 탐색기에서 위치를 열어 사용자가 직접 판단하게 합니다.
- 링크 주소는 앱이 만든 값이 아니라 **문서를 쓴 사람이 적은 값**입니다. 그래서 허용 목록을 화면(프런트) 쪽이 아니라 앱 뒤쪽에 두었습니다.

## 알아 둘 점
- 앱 권한 설정(`capabilities`)은 한 글자도 바꾸지 않았습니다. 웹 주소 열기는 이미 허용돼 있던 경로를 제대로 부르도록 고친 것이고, 로컬 파일은 앱 자신의 커맨드로 처리합니다.
- `file://server/share` 처럼 호스트가 붙은 주소(UNC)는 다루지 않습니다.
