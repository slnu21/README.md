# 2026-10-11 (07) [v1.0 U6] 출하 확인 항목 — 브리지가 떠 있는 채로 업데이트

브랜치 `develop-update-check` · 문서만(로드맵)

## 배경

(06)의 실구동 검증이 Store 설치본 브리지(`readme-md mcp`, 다른 Claude Code 세션)에 막혔다. 사용자 질문: "DB 잡혀 있는
건 실사용에서는 문제 아닌가?"

- **막힌 원인은 검증 스크립트였다** — `userdata.ps1` 이 데이터 폴더를 통째로 옮기는데, Windows 는 열린 파일이 든 폴더의
  이름을 못 바꾼다. 앱과 브리지의 동시 사용과는 다른 문제다.
- **동시 사용은 설계돼 있다** — 둘 다 `db::open_at` 의 같은 PRAGMA(WAL · `busy_timeout` 5000)로 연다. 브리지는 읽기
  위주이고 마이그레이션은 앱만 한다. (06) 실구동의 MCP 항목이 바로 앱이 떠 있는 채 파이프로 부른 경우였고 정상이었다.
- **남는 빈칸은 업데이트다** — 브리지는 클라이언트 세션 내내 살고 DB 연결도 하나를 계속 든다(`mcp/mod.rs`
  `run_stdio`). 그 상태로 Store 가 판을 바꾸면 업데이트가 미뤄지는지 / 프로세스를 끝내는지, 살아남은 옛 브리지가 새
  스키마를 읽어도 되는지 아무도 재 보지 않았다. 1.0 은 이 브리지를 헤드라인으로 낸다.

## 변경

- `docs/design/roadmap-1.0.md` U6 에 확인 항목 하나: 임시 신원 MSIX 두 판(v3 → v4)으로 ① 업데이트 동작 ② 옛 브리지 ×
  v4 DB ③ 판올림 × 옛 연결 ④ 재연결. 고칠 거리가 나오면 출하 전에 고친다.
