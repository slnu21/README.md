# 2026-09-19 (01) v0.10.0 배포 준비 갱신 — RTL 을 같은 판에 태워 재빌드

브랜치 `develop-release-v0100-rtl` · 머지 `ae3864d` · 커밋 `5d4abf5` · WBS #865

## 배경

RTL 요청은 Store 후기에서 왔다 — 요청자가 확인하려면 MSIX 로 나가야 한다. "0.11.0 으로 낼까"가
질문이었는데 확인해 보니 전제가 달랐다: **v0.10.0 은 2026-09-09 에 배포 준비만 되고 GitHub·Store
어디에도 나간 적이 없었다**(태그 최신 `v0.9.0` · `origin/main` 이 v0.9.0 릴리스 완결 머지 · 설치된
Store 판 `0.9.0.0` · 리스팅 체크리스트 v0.10.0 항목 미체크 — 직전 배포 준비 커밋 끝줄 "push · GitHub
릴리스 · Store 제출은 사용자 확인 후"가 그대로 남아 있었다). 아무 데도 안 나간 버전은 SemVer 상 올릴
이유가 없고, 0.6.7 처럼 번호를 건너뛰면 CHANGELOG 에 안 나간 [0.10.0] 이 남는다. 세 안 중 **0.10.0 에
태워 한 번에**를 사용자가 골랐다.

## 결정·함정

- **"이미 나갔다"는 확인하기 전엔 전제로 삼지 않는다** — CLAUDE.md 다음 단계에 "v0.10.0 으로 나갔다"고
  적혀 있었고 그 문장이 판단을 한 번 비틀었다. 릴리스 상태는 태그·`origin/main`·`Get-AppxPackage` 셋으로 본다.
- **worktree 에는 `.cargo/config.toml` 이 없다**(로컬 파일) → target 이 worktree 안에 생겨 풀빌드가
  된다. 패키징 스크립트는 `_paths.ps1` 이 같은 규칙으로 target 을 찾으니 결과는 맞다. 빠르게 하려면
  worktree 의 `src-tauri/.cargo/config.toml` 을 복사해 두면 된다(D: 공유 target).
- 산출물 크기가 이전 준비본과 KB 단위로만 다르다 — 프런트에 RTL CSS·확장 몇 KB 가 늘었을 뿐이다.
  `_paths.ps1` 의 FileVersion 가드는 같은 0.10.0 이라 낡은 exe 를 못 가르므로 **exe 타임스탬프**를 봤다.
