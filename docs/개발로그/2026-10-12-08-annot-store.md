# 2026-10-12 (08) [v1.1 V2] 표시 펜 저장 — 마이그레이션 v5 · 판 고정 · 참조된 판은 정리에서 제외

브랜치 `develop-annot-store` · [ADR 0003](../design/decisions/0003-annotation-pens.md) 단계 ③ · [roadmap-1.1.md](../design/roadmap-1.1.md) V2

## 배경

표시는 "그 판의 몇 번째 글자부터 몇 번째까지"를 기억한다. 그러려면 표시를 다는 순간의 판이 기록에 **있어야 하고**,
**계속 남아 있어야** 한다. 기존 기록은 "덮이기 직전의 옛 내용"만 뜨고, 문서당 30판 · 전체 2,000판에서 오래된 것부터
버린다 — 그대로 두면 바쁜 문서에서 바탕 판이 조용히 지워진다.

마이그레이션은 확인 게이트지만, 사용자가 표시 펜을 "목업으로 확인했으니 자율 진행"으로 지시했고 이 판올림은 표 하나를
더하는 것뿐이라 그 지시를 승인으로 봤다((05) 결정). 대신 실사용 DB 사본 리허설을 완료 조건에 뒀다.

## 변경

- `db.rs` **v5** — `annotation` 표(ADR 스키마) + 색인 둘. `snapshot_id` 는 **`doc_snapshot` 외래 키**.
- `commands/history.rs`
  - `prune` — 참조된 판은 문서별·전체 정리 모두에서 뺀다(`AND id NOT IN (SELECT snapshot_id FROM annotation)`).
  - `pin` — 지금 판 고정: 같은 (경로, mtime) 판이 있으면 그것, 없으면 디스크에서 읽어 **합치기 창 무시**. 색인 대상이 아닌
    낱개 문서도 된다. 1MB 초과는 거절(ko/en).
- `commands/annot.rs`(신설) — `annot_add`·`annot_list`·`annot_update`·`annot_delete`.
  - add 는 **고정 · 검사 · 넣기 · 정리를 한 트랜잭션**으로(`BEGIN IMMEDIATE`). 정리는 넣은 *뒤* — 먼저 하면 참조 없는 새 판이 지워질 수 있다.
  - 값 좁히기: kind·style(kind 별)·color 열거값 · id 영숫자·`-` · 문맥 256자 · 메모 1만 자.
  - **경합 방지**: 그 판(정규화: BOM 제거 · LF)의 UTF-16 범위 글이 `quote` 와 같아야 한다 — 미리보기를 그린 뒤 디스크가
    바뀌었으면 "문서가 방금 바뀌었습니다 — 다시 열고 표시하세요"(ko/en).
  - list 는 표시 + 가리키는 판 원문(중복 없이) — 프런트가 지금 판으로 옮길 때 쓴다.
  - update 의 `note: null` 은 메모 지우기, 키 없음은 그대로(이중 Option).
- `perf.rs` 리허설에 v5 확인 둘(빈 표 · 외래 키).
- `docs/design/data-model.md` — `annotation` 절.

## 함정

- **외래 키라서 정리 조건을 빠뜨리면 DELETE 가 통째로 실패한다** — 조용히 지우는 것보다 낫지만 정리가 멈춘다. 그래서
  조건이 테스트로 지켜진다. 같은 성질이 옛 판(1.0) 하위 호환에서는 보호막이 된다.
- 오프셋 단위는 **UTF-16** — JS 문자열 위치 그대로. Rust 에서 `encode_utf16` 으로 잘라 비교한다(UTF-8 바이트로 자르면
  한글·이모지에서 어긋난다 — 테스트에 이모지 뒤 글자).
