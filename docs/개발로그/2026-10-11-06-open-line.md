# 2026-10-11 (06) 에이전트 브리지 `open_in_app(line)` — 열면서 그 줄로

브랜치 `develop-open-line` · WBS #921(U2 브리지 실사용 — 쓰기 전에 아는 후보를 먼저)

## 배경

`outline`·`read_section` 은 줄 번호를 주는데 `open_in_app` 은 `path`·`beside` 만 받아서, 에이전트가 "3절 결론을 보세요"
하며 문서를 띄우면 사람은 언제나 맨 위에서 다시 찾아야 했다. 로드맵이 이미 아는 후보로 적어 둔 것을 실사용 기록 전에
먼저 했다(사용자 "진행해둬").

## 변경

- **도구**(`mcp/tools.rs`): 스키마에 `line`(integer, minimum 1, "outline/read_section 이 준 1-based 줄"). `line_arg` 가
  정수·숫자 문자열 ≥1 만 받고 0·음수·소수·문자는 도구 오류. 결과에 `line` 을 돌려준다.
- **argv 는 한 토큰 `--line=N`**(`launch_args`) — 두 토큰이면 숫자가 경로 후보로 읽힐 수 있다(첫 "존재하는 파일"을 고른다).
  `lib.rs` `line_from_args` 는 argv[0] 을 건너뛰고 대소문자 무시, 잘못된 값은 무시.
- **웜/콜드 두 길**: single-instance 콜백이 `open-file`(·`-beside`) 다음 `reveal-line {path,line}` 을 쏜다 /
  콜드는 `take_pending_open` 이 `{path, line}`(`PendingFile`)을 돌려준다. 프런트는 스토어 `reveal`(비영속, seq) 하나로 받는다.
- **언제 스크롤하나가 핵심**(`app/lib/reveal.ts` + `Preview.tsx`) — pane-a iframe 은 탭을 바꿔도 다시 안 만들어져서
  요청 순간엔 **앞 문서**가 들어 있고, 곧 올 load 의 위치 복원이 덮는다. iframe 에 그려진 경로를 따라가(본문 경로 →
  srcdoc 경로 → load 된 경로 · in-flight) 지금 할지 다음 load 에 할지 정하고, 미룬 요청은 **그 경로의 load 에서만** 쓴다
  (아니면 나중 타자 한 번에 그 줄로 튄다). 탭이 바뀌면 미룬 요청은 버린다. 편집기는 문서마다 재마운트되므로 활성 문서가
  된 다음 렌더에 `scrollToLine`.

## 검증하다 나온 곁다리 고침 둘(원래 있던 버그)

실물 검증 첫 판은 13항목 PASS 였는데 숫자 하나가 이상했다 — 옆 패널을 연 뒤 주 패널 Gamma 의 scrollTop 이 직전 Beta 의
위치(2681)와 **같았다**. 시간대별로 찍어 보니:

1. **다른 문서를 열면 앞 문서 위치에서 열렸다**(v0.6.5 `restoreLineRef` 부터) — 복원이 문서가 바뀌었는지를 안 봤다.
   Alpha 를 150줄에 둔 채 줄 없이 Beta 를 열면 Beta 도 3341px. → `restoreLineFor`: load 된 경로 = 다음 경로일 때만.
   **이게 있으면 줄 이동 검증이 복원 덕에 우연히 통과할 수 있다** — 그래서 검증 순서를 "앞 문서가 맨 위인 상태에서
   다른 문서를 줄과 함께"로 바꿨다.
2. **옆 패널을 열면 주 패널이 맨 위로** — 리딩 분할이 편집기를 `display:none` 으로 숨기면 편집기가 scrollTop 0 으로
   scroll 을 한 번 쏘고, 동기화가 미리보기를 끌어올렸다. → 편집기 방출 쪽에서 `clientHeight` 0 이면 안 쏜다.
3. (이번 기능의 군더더기) 편집기를 그 줄로 옮기면 동기화가 **아직 앞 문서가 든** 미리보기를 잠깐 움직였다(Gamma@2681 →
   Beta 로드). → 미리보기 `scrollToLine` 은 그 패널의 문서가 그려져 있을 때만(`canSyncScroll`).
