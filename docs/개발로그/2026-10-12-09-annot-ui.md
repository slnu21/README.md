## 프로브가 잡은 것 (전부 고침)

1. **옛 DOM 위에 새 글의 위치를 그렸다** — 문서가 바뀌면 버퍼로 즉시 다시 계산했는데, 새 렌더는 디바운스·워커 뒤에 온다 → 표시가 엉뚱한 줄로
   튀었다가 돌아온다. iframe 에 **지금 그려진 글**(`loadedContent`)로만 계산한다.
2. **문단을 끼우고 바로 아래 문단을 고치면 칠한 자리가 끼운 문단으로 갔다** — 줄 diff 가 그 사이 빈 줄을 맞추며 옛 문단을 끼운 문단과 짝지었다.
   덩어리 사이 빈 줄 eq 를 덩어리로 합치고, **덩어리 안에서는 닮은 줄끼리 먼저 짝짓는다**(순서 보존 · 유사도 합 최대 DP). 짧은 문단으로는 재현이
   안 돼(Myers 가 다른 길을 고른다) 실제 픽스처로 테스트를 박았다 — 고치기 전 FAIL 확인.
3. **고친 문단 바로 아래 문단을 지우면 지운 문장의 표시가 "바뀜"이 됐다**(요약 테스트에서) — 낱말 diff 의 공백 합치기가 순수 삭제 쪽으로도 번졌다.
   양쪽이 둘 다 바꾸기일 때만 합친다 + 위 2의 줄 짝짓기.
4. **질감이 다시 칠하기를 두 배로** — 필터 영역이 층 전체(카드)라 957px 카드에서 16.7 → 33.3 ms/프레임. 표시마다 자기 상자에 걸어 16.7 = 16.7.
   프로브가 이제 "질감 켬이 한 프레임 넘게 느리면 FAIL" 을 지킨다(ADR 의 "끄는 기준은 실측으로").
5. **가운데 정렬 카드 옆에는 1600px 창에서도 레일 자리가 없다** → 펼치면 카드를 왼쪽으로 비킨다. 처음엔 비킨 뒤의 폭으로 재서 언제나 "들어간다"고
   나왔다(900px 에서도 레일) — 비키기 전 폭으로 잰다.
6. 부모 문서의 Esc 가 트레이를 못 닫았다(리스너가 iframe 에만) · `?demo` 경로는 테마·줌·리딩 폭에 iframe 을 다시 안 만든다(프로브는 `&worker`).
