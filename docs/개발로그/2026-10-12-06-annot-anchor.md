## 배경

표시 펜에서 가장 어려운 곳(ADR "렌더 글자 ↔ 소스 글자")을 화면·저장보다 먼저 순수 로직으로 닫는다. 표시의 위치는
**스냅샷 원문의 글자 범위**이고, 열 때마다 지금 판으로 옮긴다 — 그 옮기기와, 미리보기에서 고른 글자를 소스 범위로
바꾸는 일이 전부 여기 있다. 새 의존성 0.

## 변경 — `src/app/lib/annot/`

- `diff.ts` — `diffSeq`(Myers, 앞뒤 공통부를 먼저 떼고 편집 2,000 넘으면 덩어리 하나 · 메모리 O(D²)) ·
  `textSegments`(줄 diff → 바뀐 덩어리 안은 **낱말 단위** diff → 두 글을 빈틈없이 덮는 글자 구간).
- `relocate.ts` — `Relocator(옛 글, 새 글).relocate(start, end)` → 상태 넷(same·moved·changed·gone) + 지금 범위 +
  이전/지금 글. `canonicalText`(BOM·CRLF → 표시의 위치 기준) · `lineAt`.
- `quote.ts` — TextQuote(`quote`·`prefix`·`suffix`) 만들기/찾기. 같은 글이 여럿이면 문맥이 길게 맞는 쪽 → hint 에 가까운 쪽.
  못 찾으면 null(억지로 비슷한 것을 고르지 않는다).
- `sourceMap.ts` — `visibleChars`(줄 머리 기호·링크 주소·이미지·HTML 태그·표 구분 행·참조 정의를 뺀 소스) →
  `alignRendered`(렌더 글과 글자 diff, 타이포그래퍼 따옴표·줄표·말줄임을 같은 글자로) → `renderedToSource`/
  `sourceToRendered`. `rangeable`(코드·mermaid·수식 블록은 범위 펜 불가).

## 함정 (테스트가 잡은 것)

- **다시 쓴 문장에서 공백이 우연히 맞는다** — "근거가 부족하다 — 측정은 한 번뿐이었다." → "세 번 다시 재서 확인했다."
  에서 칠한 범위가 `세 번` 으로 줄었다(낱말 diff 가 공백끼리 맞춤). 바뀐 것 *사이에 낀* 공백·구두점뿐인 eq 는 바뀐 것으로
  합친다. 한 낱말만 고친 경우는 앞뒤가 eq 라 영향이 없다.
- **범위 바로 앞에 끼어든 글이 범위에 섞일 뻔했다** — 경계 위치 p 를 옮길 때 시작은 p 에서 *시작하는* 글자의 구간,
  끝은 p 에서 *끝나는* 글자의 구간으로 봐야 한다(설계 단계에서 고침, 테스트 "(주) … (재확인)").
- **링크 주소를 남기면 정렬이 동점으로 갈린다** — `[a](http://x)hello` 의 `hello` 가 주소의 `h` 에 맞을 수 있다. 글자를
  가진 숨은 문법은 정렬 전에 뺀다. 기호(`*`·`_`)는 남겨도 정렬이 건너뛴다.

## 남은 것 (V3 에서)

- 블록의 소스 줄 범위가 필요하다 — 지금 렌더러는 `data-line`(시작 줄)만 찍는다. V3 에서 `data-line-end` 를 더한다.
- 여러 블록에 걸친 범위는 블록마다 잘라 그린다(DOM 쪽 일).
