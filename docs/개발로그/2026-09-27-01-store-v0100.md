# 2026-09-27 (01) v0.10.0 Microsoft Store 게시 완료 — 별칭·브리지 실측

브랜치 `develop-store-v0100` · 머지 `<merge-hash>` · 커밋 `<hash>` · WBS #905

## 배경

v0.10.0 은 GitHub 릴리스(2026-09-19)까지 나가고 Store 제출은 사용자 직접이었다. 제출·인증·게시가
끝나 확인하는 단위다. 이번 판은 **RTL 을 요청한 Store 후기의 답**이기도 해서, 게시 여부와 함께
**요청자가 실제로 쓸 수 있는 상태인지**가 확인 대상이다. 개발자 답글(영문)도 게시했다.

## 변경

문서만. `docs/deployment/store-listing.md` 등록 체크리스트 v0.10.0 항목 `[ ]` → `[x]`(게시 확인 근거
포함) · `CLAUDE.md` 현재 상태에 게시 완료와 아래 실측.

- **App Execution Alias**(v0.10.0 이 첫 출하) — `Get-Command readme-md` → `%LOCALAPPDATA%\Microsoft\

- **브리지 핸드셰이크**(`readme-md.exe mcp`, stdio) — `initialize` → `protocolVersion 2024-11-05` ·

  delete 이름 0** · stderr 비어 있음. 문서는 읽지 않았다(`tools/call` 없음).
- **시작 메뉴 항목 1개** — `Get-StartApps` 에 `README.md` / `SlnU.README.md_fqpsajc525k1c!Gyeol` 하나뿐.

## 결정·함정

- **ADR 0002 의 예측이 서명된 실물에서 그대로 나왔다.** 2026-09-06 프로브(버리는 패키지)로 "alias
  Extension 하나만 얹으면 앱 목록이 그대로"를 쟀는데, Store 재서명을 거친 실물도 같았다. Atlas 가
  `<Application>` 을 셋 두어 "앱이 안 켜진다" 리뷰를 받았던 사고는 재현되지 않았다.
- **핸드셰이크는 DB 를 안 건드린다** — MCP 모드는 `tauri::Builder` 이전 분기고 `open_workspace_db` 는
  파일이 없으면 만들지 않고 안내 문자열을 돌려준다(`mcp/mod.rs:65`). 그래서 사용자 실제 DB 를 비켜
  놓지 않고도 안전하게 확인할 수 있었다 — **앱 창을 띄우는 검증과 규칙이 다르다**(그쪽은 `userdata.ps1`).
