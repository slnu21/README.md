# 받은 문서함

에이전트(또는 다른 프로그램)가 만지고 간 문서를 사람이 **알아채게** 한다.

[에이전트 브리지](agent-bridge.md)가 "에이전트가 이 워크스페이스를 본다"는 쪽이라면, 이쪽은 그
반대 방향이다 — 밤새 에이전트가 써 놓은 것을 아침에 앱을 열었을 때 눈에 띄게 하는 것.
브리지 없이도 값이 있다: 감시기는 **누가 고쳤든** 파일 변경을 본다.

## 원천은 색인이다 — 새로 만든 것은 "본 시점" 하나뿐

색인이 이미 파일마다 mtime 을 들고 있다(`file_meta.mtime`). 그래서 새 테이블은 하나면 된다.

```
doc_seen(real_path PRIMARY KEY, seen_mtime, seen_at)
```

**받은 문서함 = `file_meta.mtime > doc_seen.seen_mtime` 이거나 `doc_seen` 행이 아예 없는 것.**
후자는 "한 번도 본 적 없는 문서" = **새 문서**로 표시한다.

앱이 꺼져 있는 동안 바뀐 것도 함께 잡힌다 — 부팅 재색인이 mtime 을 올려 주기 때문이다.
그게 사실 제일 중요한 경우다.

## 신호를 죽이지 않는 규칙 셋

이 기능은 "안 본 것"이 실제로 안 본 것일 때만 값이 있다. 셋 중 하나만 어겨도 소음이 된다.

1. **판올림 때 이미 색인된 것은 전부 '본 것'으로 친다**(마이그레이션 v2 가 `file_meta` 를 그대로
   복사한다). 안 그러면 판올림 첫 실행에 수천 건이 뜬다.
2. **폴더를 처음 가져올 때는 그 안의 문서를 전부 '본 것'으로 친다**(`index_folder` 의 `fresh_root`).
   가져오자마자 수백 건이 뜨면 아무도 안 본다. 반대로 **이미 아는 루트를 다시 훑는 것**(부팅
   재색인)이면 바뀐 것은 알림 대상이 맞다.
3. **앱이 쓴 것은 곧바로 '본 것'으로 표시한다**(`fs_ops` 의 `write_file`·`create_file`).
   내가 방금 저장한 문서가 받은 문서함에 뜨면 그 순간 신호가 죽는다. 이때 mtime 은 **디스크에서
   다시 읽는다** — 색인이 아는 값은 아직 낡아서, 그걸 박으면 곧이어 재색인이 새 mtime 을 넣으며
   결국 뜬다.

## 화면

- 툴바의 **알림 종** — 누르면 팝오버로 펼쳐진다. 최신 순, 항목마다 `새 문서`/`변경됨`과 시각.
  **배지는 0일 때 안 나온다**(0을 띄우면 늘 붉은 점이 있는 셈이다).

  > **사이드바 탭이 아니라 종인 이유**: 워크스페이스·최근은 *탐색하는 자리*지만 이건 *소식*이다.
  > 읽고 나면 비는 목록에 탐색 탭과 같은 자리를 줄 이유가 없고, 탭을 셋으로 늘리면 한국어 라벨이
  > 248px 사이드바에서 잘린다(실제로 잘렸다). 종은 어느 탭을 보고 있든 눈에 띈다.
- 워크스페이스 트리의 **점** — 폴더를 펼쳐 둔 사람은 목록보다 여기서 먼저 본다. 점의 원천은
  받은 문서함 목록 그 자체다(상태를 둘로 두면 반드시 어긋난다).
- **항목을 누르면 그 문서가 열리고 목록에서 빠진다.** 마지막 하나를 열면 팝오버도 닫힌다.
- **문서를 (어디서든) 열면 빠진다.** 화면은 IPC 왕복을 안 기다리고 먼저 지운다 — 클릭하자마자 점이
  사라져야 자연스럽다.
- **[모두 읽음]** — 색인이 아는 모든 문서의 현재 mtime 을 그대로 박는다.

## 범위

워크스페이스 안쪽만 본다([스코프](agent-bridge.md#스코프--에이전트가-볼-수-있는-범위)와 같은
판정을 쓴다 — `scope.rs`). 색인에는 예전에 가져왔다가 뺀 폴더의 경로가 남아 있을 수 있고,
그것까지 보여 주면 받은 문서함이 신호가 아니라 소음이 된다.

## 함정

- **팝오버 안의 버튼은 툴바 `.seg` 안에 있다** — `.seg button`(명시도 0,1,1)이 가운데 정렬과
  24px 고정 높이를 준다. 클래스 하나(0,1,0)로는 못 이겨 `.inbox-pop .inbox-item` 처럼 둘로
  올려야 한다. 캡처를 보기 전에는 안 보였고, 두 번 데었다.

- **`INSERT ... SELECT ... ON CONFLICT` 는 SQLite 가 파싱하지 못한다** — `ON` 을 조인으로 읽는다.
  `SELECT ... WHERE true ON CONFLICT ...` 로 갈라 줘야 한다([모두 읽음]이 이 형태다).
  단위 테스트가 이걸 잡았다.
- 마이그레이션은 **append-only** 다. `doc_seen` 은 v2 이고, 기존 단계는 절대 고치지 않는다.

## 검증

- 단위 테스트 5종 — 처음 보는 파일 / 표시 후 다시 바뀜 / 주어진 mtime 을 그대로 씀 / 모두 읽음 /
  **판올림이 기존 색인을 전부 '본 것'으로 넘기는지**(실제 마이그레이션을 태워서 확인한다).
- **실구동 7항목**(WebView2 CDP) — 임시 폴더를 새로 가져와 비어 있음 확인 → 밖에서 고침(변경됨)
  → 밖에서 새로 만듦(새 문서) → 배지 숫자 → 열면 빠짐 → **앱에서 저장한 것은 안 들어옴** →
  모두 읽음. 사용자 데이터는 `video/capture/userdata.ps1` 로 폴더째 비켜 놓는다.
