# 문서 기록 (로컬 스냅샷)

**"AI 가 내 문서를 덮어썼다"를 되돌릴 수 있게 한다.** [받은 문서함](inbox.md)이 *알아채게* 하는
쪽이라면, 이쪽은 *되돌리게* 하는 쪽이다. 둘이 한 짝이다 — 알아챈 다음에 할 수 있는 일이 있어야
한다.

## 되돌리려면 바뀌기 *전* 내용이 있어야 한다

그런데 우리는 남의 쓰기를 가로챌 수 없다. 파일이 바뀐 뒤에야 감시기가 알려 준다.

**그런데 색인이 이미 파일 내용을 통째로 들고 있다**(`file_index.content`). 그래서 재색인이 옛
내용을 새 내용으로 덮기 **직전**이 마지막이자 확실한 기회다 — 거기서 한 벌 뜬다. 앱이 직접
저장할 때도 덮어쓰기 전에 같은 함수를 부른다(그쪽은 디스크에서 바로 읽는다). 파일이 색인에서
빠질 때(= 지워졌을 때)도 마지막 내용을 뜬다 — **지워진 문서야말로 되돌리고 싶은 것**이다.

```
doc_snapshot(id, real_path, mtime, taken_at, content)
```

`mtime` 은 **그 내용이 디스크에 있던 시각**이라 목록에 그대로 보여 줄 수 있고, `(real_path, mtime)`
유니크 인덱스가 **같은 판을 두 번 뜨는 것을 막는다** — 저장 경로와 색인 경로가 같은 판을 노리기
때문이다.

## 쏟아지지도, 무한정 자라지도 않게

| 규칙 | 값 | 이유 |
|---|---|---|
| 합치기 창 | 60초 | 자동저장이 도는 동안 판이 쏟아지면 기록이 쓸모없어진다 |
| 문서당 상한 | 30판 | 오래된 것부터 버린다 |
| 저장소 전체 상한 | 2,000판 | 문서 수가 많아도 무한정 자라지 않게 |
| 내용 크기 상한 | 1MB | 기록 하나가 DB 를 삼키면 안 된다 |

**합치기 창은 지키고 싶은 경우를 안 건드린다.** 저녁에 편집을 멈추고 새벽에 에이전트가 덮어쓰면
마지막 판이 몇 시간 전이라 창에 걸리지 않는다. 창에 걸리는 것은 *연달아* 일어나는 변경뿐이다.

**되돌리기 직전 스냅샷만 창을 무시한다.** 거기서 못 뜨면 지금 내용이 영영 사라지기 때문이다 —
그래서 **되돌리기 자체도 되돌릴 수 있다**.

## 화면

탭 우클릭 → **[문서 기록]**(명령 팔레트에도 있다). 왼쪽에 판 목록(시각·크기), 오른쪽에 그 판의
내용. [이 판으로 되돌리기]를 누르면 디스크를 그 내용으로 덮고, 열린 탭도 그 자리에서 갱신한다.

**저장하지 않은 편집이 있으면 되돌리기를 막는다.** 되돌리기는 디스크를 덮는데 기록은 *저장된
것*만 알기 때문이다 — 그 편집만 되살릴 길이 없다.

되돌린 파일은 [받은 문서함](inbox.md)에 뜨지 않는다(내가 한 일이다).

## 한계 (알고 두는 것)

- **색인 대상만 기록된다** — `.md`·`.markdown`·`.mdx`·`.txt`, 워크스페이스 안쪽. 색인이 원천이라
  그렇다.
- **첫 색인에는 기록이 없다** — 덮을 옛 내용이 없기 때문이다. 폴더를 가져온 그 순간부터 쌓인다.
- **앱이 꺼져 있는 동안 두 번 바뀌면 중간 판은 없다.** 부팅 재색인은 마지막 상태만 본다. 남는
  것은 "앱이 마지막으로 알던 내용"이고, 그게 대개 되돌리고 싶은 그것이다.
- 지워진 문서의 기록은 남지만 화면에서 여는 길이 아직 없다(탭이 없으므로). 저장소 상한 안에서
  보존된다.

## 검증

- 단위 테스트 7종 — 덮이기 직전 내용 포착 / 같은 판 중복 방지 / 합치기 창 / **밤새 변경은 창에
  안 걸린다** / 문서당 상한 / 크기 상한 / **바쁜 문서가 조용한 문서의 기록을 밀어내지 않는다**.
- **실구동 8항목**(WebView2 CDP) — 가져온 직후엔 기록 없음 → 밖에서 덮어쓰기 → 원본이 남음 →
  되돌리기(디스크·탭·되돌리기의 되돌리기) → **탭 우클릭 메뉴에서 모달이 열리고 목록이 그려짐** →
  합치기 창 60초를 실제로 기다린 뒤 앱 저장도 한 판 남김. 사용자 데이터는
  `video/capture/userdata.ps1` 로 폴더째 비켜 놓는다.
