# ADR 0002 — 에이전트 브리지(MCP): 단일 바이너리 모드 분기

- 상태: 채택(Accepted)
- 날짜: 2026-09-06

## 맥락

이 앱의 서사는 **"에이전트가 쓴 문서를, 사람이 읽는 자리"** 다. 그런데 지금 흐름은 단방향이다 —
에이전트가 디스크에 md 를 쓰고, 사람이 앱을 열어 찾아 읽는다. 에이전트는 사람이 만든 워크스페이스
배치를 모르고, 방금 쓴 문서를 사람 화면에 놓을 수도 없다. v1.0 의 헤드라인으로 이 고리를 닫는다.

제약 셋이 설계를 거의 결정한다.

1. **100% 오프라인 표명** — Store 리스팅·README·CSP 가 전부 이것을 전제로 한다.
2. **MSIX → Store 배포** — 패키지 신원·쓰기 가상화·앱 목록이 전부 여기 걸린다.
3. **앱 목록 항목이 곧 UX** — 아래 선행 사례.

### 선행 사례 — Atlas 가 같은 자리에서 리뷰를 잃었다

같은 계정의 Atlas 는 GUI + CLI + MCP 세 exe 를 MSIX 에 담으면서 exe 마다 `<Application>` 을 두었다.
결과는 시작 메뉴에 **아이콘이 같은 항목 셋**(`Atlas` · `Atlas CLI` · `Atlas MCP`)이었고, 그중 둘은
눌러도 창이 안 뜬다. 사용자에게 그것은 "헷갈린다" 가 아니라 **"앱이 안 켜진다"** 이고, 실제로 스토어
리뷰가 나빠졌다. 2026-09-06 에 원인과 해법을 실측으로 확인해 Atlas 를 항목 1개로 되돌렸다
(사이클 185). **md-reader 는 그 결론을 처음부터 설계에 넣는다.**

## 결정

1. **MCP 서버는 `md-reader.exe` 의 한 모드다. 새 exe 를 만들지 않는다.**
   `main()` 에서 `tauri::Builder` 를 세우기 **전에** argv 를 보고 갈라진다. MCP 모드면 창을 띄우지
   않고 stdio 루프만 돈다.
2. **전송은 stdio.** `127.0.0.1` HTTP/SSE 서버를 열지 않는다.
3. **MSIX 노출은 기존 단일 Application 에 alias Extension 하나** — `readme.exe` 별칭이
   `md-reader.exe` 로 해석된다. 새 `<Application>` 은 **0개**이므로 앱 목록은 지금 그대로
   `README.md` 하나다.
4. **도구 표면 원칙: 파일시스템이 이미 하는 일은 주지 않는다.**
   에이전트는 이미 md 를 읽고 쓰고 grep 한다. 우리가 줄 수 있는 것은 이 앱만 아는 넷뿐이다.

   | 분류 | 도구 | 이 앱만 아는 것 |
   |---|---|---|
   | 읽기 | `search_docs(query, root?, limit?)` | FTS5 색인 — grep 이 못 하는 랭킹 검색 |
   | 읽기 | `outline(path)` | 헤딩 트리(`id`·`data-line`) |
   | 읽기 | `read_section(path, heading\|range)` | 섹션만 읽어 토큰 절약 |
   | 읽기 | `list_workspace(folder?)` | 가상 폴더 그래프 = 사람이 만든 배치 |
   | 제어 | `place_doc(path, folder)` | 워크스페이스에 참조 추가(**파일은 안 옮긴다**) |
   | 제어 | `open_in_app(path, pane?, line?)` | 사람 화면에 띄우기 |

   `write_doc`·`create_doc`·`delete` 는 **제공하지 않는다.** fs 가 이미 하는 일을 중복으로 열면
   값은 0 이고 프롬프트 인젝션 표면만 는다.
5. **제어 도구(5·6)는 설정의 '에이전트 연결' 패널이 생긴 뒤에 연다.** 사용자가 상태를 보고 끌 수
   없는 원격 제어는 열지 않는다.

## 근거 — 2026-09-06 실측

버리는 프로브 패키지 둘(Rust · .NET)을 개발자 모드로 등록해 쟀다. 전부 이 결정의 전제다.

| 잰 것 | 결과 | 이 결정에 주는 뜻 |
|---|---|---|
| windows-subsystem exe + 파이프 stdio | **동작**(ECHO 왕복) | Tauri 바이너리 그대로 MCP 서버가 된다 |
| 별칭 실행 시 패키지 신원 | **유지**(직접 실행은 `NO_PACKAGE`) | MCP 모드가 GUI 와 **같은 물리 데이터 폴더**를 본다 |
| 네이티브 `argv[0]` | **별칭 경로 보존** | Rust 는 `std::env::args()` 로 충분(.NET 과 다르다) |
| alias Extension 의 `Executable=` | **부모와 다른 exe 가능** | Application 을 안 늘리고 별칭을 달 수 있다 |
| 한 Extension 에 `ExecutionAlias` 여러 개 | **가능** | 별칭이 늘어도 항목은 안 는다 |
| `AppListEntry="none"` | **Store 자동 거부**(헤드리스 앱) | 숨기는 길은 없다 — 안 만드는 게 답이다 |

`app_paths.rs` 의 컨테이너 판정(v0.9.0)이 **MCP 모드에서 그대로 유효**하다는 것이 특히 중요하다.
별칭으로 뜬 프로세스가 패키지 신원을 가지므로 같은 가상화 뷰를 보고, 따라서 같은 `md-reader.db` 를
연다. 신원이 없으면 `%APPDATA%` 쪽 빈 DB 를 열어 **"워크스페이스가 비었다"** 로 보였을 것이다.

### 로컬 HTTP 서버를 안 쓰는 이유

포트를 열면 (a) "원격/CDN 금지 · 100% 오프라인" 표명이 흔들리고, (b) 인증·바인딩 표면이 생기고,
(c) Store 심사에서 설명해야 하고, (d) **앱이 떠 있어야만** 에이전트가 쓸 수 있다. stdio 는 넷 다 없다.

## 영향

- **Cargo bin target 추가 없음.** 다만 MCP 프로토콜 구현 크레이트는 새 의존성이므로 **확인 게이트**다
  (직접 구현 vs 크레이트 채택은 미결).
- **분기 위치가 계약이다** — SQLite 마이그레이션(`db::init`)·single-instance 플러그인 등록보다
  먼저 갈라져야 한다. 뒤에 두면 에이전트가 붙을 때마다 사용자 앱 상태를 건드린다.
- **`open_in_app` 은 기존 single-instance argv 전달을 재사용한다.** `lib.rs` 의
  `first_openable_arg` 가 이미 플래그(`-` 시작)를 건너뛰므로 `--beside` 같은 확장 여지가 있다.
- **검색은 반드시 스코프.** `search_query` 에 이미 `path_prefix` 인자가 있다. 전역 검색은 머신 전체
  인덱스를 조회하므로(`AppShell.tsx` → `search.rs`) 워크스페이스 루트로 좁히지 않으면 사용자의
  무관한 문서가 에이전트에게 샌다.
- **사람이 터미널에서 부르는 CLI 는 출력이 안 보인다** — windows-subsystem 바이너리라
  `AttachConsole(ATTACH_PARENT_PROCESS)` 가 필요하다. MCP(파이프) 경로에는 영향 없다.
- **별칭은 사용자가 끌 수 있다**(설정 → 앱 → 고급 앱 설정 → 앱 실행 별칭). 연결 패널이 이를 감지해
  안내해야 "설정대로 했는데 안 돼요" 를 막는다.
- 오프라인 표명·CSP 무변경.

  `initialize`·`tools/list`·`tools/call`·알림 무시뿐이라 `serde_json` 으로 충분했다. **새 의존성 0**,

- 제어 도구 권한 모델(도구별 토글 / 1회 확인 / 로그).
