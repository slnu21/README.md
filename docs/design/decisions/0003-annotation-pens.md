# ADR 0003 — 표시 펜: 스냅샷에 고정한 글자 앵커 위에 그린다

- 상태: 채택(Accepted) — 구현 전 설계
- 날짜: 2026-10-10
- 시안: [mockups/annotation-pens.html](../../mockups/annotation-pens.html)

## 맥락

리딩 화면에서 문서에 형광펜을 칠하고, 별표·물결 밑줄 같은 표시를 하고, 메모를 달고 싶다(사용자
제안). 처음 떠올린 모양은 **미리보기 위에 캔버스를 덮고 그리는 것**이었고, 같은 계정의 ShotLog 에 그런
도구가 있다(`ShotLog/src/ShotLog/Capture/AnnotationWindow.xaml.cs` — WPF `InkCanvas`, [완료] 시
비트맵에 픽셀로 굽는다).

**그 방식은 이 앱에서 성립하지 않는다.** ShotLog 의 바탕은 크기가 고정된 그림이라 좌표가 곧 위치다.
md-reader 의 미리보기는 **리플로우되는 문서**다.

1. **보기 설정만 바꿔도 어긋난다** — 창 폭 · 리딩 폭 · 줌 · 글꼴 · 테마(스타일 팩은 여백까지 바꾼다) ·
   RTL · 좌우 분할. 하나만 달라져도 형광펜이 엉뚱한 줄 위에 뜬다.
2. **문서가 바뀌면 더 크게 어긋난다** — 받은 문서함이 내세우는 바로 그 상황, 에이전트가 밤새 문서를
   고쳐 쓴 경우다. 문단 하나만 끼어들어도 그 아래 표시가 전부 밀린다.
3. **틀린 줄 모르고 틀린다** — 브리지가 앵커 id 를 흉내 내지 않고 줄 번호를 준 것과 같은 이유로,
   *조용히 틀린* 표시는 드러나는 오류보다 나쁘다.

그런데 표시가 가장 값진 곳도 2번이다. "여기 근거 부족"이라고 칠해 둔 문장을 에이전트가 고쳤다면,
그 사실 자체가 사람에게 필요한 정보다.

## 결정

### 1. 위치는 좌표가 아니라 **스냅샷 원문의 글자 범위**다

표시를 다는 순간 그 문서의 **지금 판을 스냅샷으로 고정**하고, 표시는 "그 판의 몇 번째 글자부터
몇 번째 글자까지"를 기억한다. 스냅샷 원문은 바뀌지 않으므로 **표시는 영원히 그 판에 대해 참이다.**

- 같은 판에 표시를 여러 개 달면 스냅샷 하나를 같이 쓴다. 판이 바뀐 뒤 새로 단 표시는 새 판을
  가리킨다. 한 문서의 표시들이 서로 다른 판을 가리킬 수 있다.
- **"지금 판에서 어디냐"는 저장하지 않는다.** 열 때마다 *표시의 판* ↔ *지금 판*을 diff 해 옮긴다.
- 스냅샷은 기존 [문서 기록](../features/history.md)의 `doc_snapshot` 을 재사용한다(아래 6절).

### 2. 지금 판으로 옮길 때 상태는 넷 — 숨기지 않고 드러낸다

| 상태 | 뜻 | 화면 |
|---|---|---|
| 그대로 | 글자가 같은 자리 | 평소대로 |
| 옮겨짐 | 위아래로 밀렸지만 글자는 같음 | 새 위치에 그대로(사용자는 차이를 못 느낀다) |
| **바뀜** | 칠한 글자가 수정됨 | 지금 판의 대응 범위에 그리고, 메모에 **이전 → 지금** 비교 + [해결됨] |
| 사라짐 | 삭제됨 | 본문에는 없음. 메모 목록에서 [그 판 보기] → 스냅샷을 읽기 전용으로 열어 원래 자리에 |

**바뀜이 가장 값진 신호다** — 지적한 자리를 누가 고쳤다는 뜻이다. [해결됨]으로 닫으면 리뷰 한 바퀴가
끝난다.

### 3. 펜은 "붙는 자리" 세 종류, 펜마다 **뜻**이 있다

| 종류 | 붙는 곳 | 펜 · 기본 뜻 |
|---|---|---|
| 범위 | 글자 A~B | 형광펜 · 중요 / 밑줄 · 기억할 것 / 물결 밑줄 · 확인 필요 / 취소선 · 빼도 됨 / 동그라미 · 용어 확인 |
| 점 | 블록의 첫 줄(왼쪽 여백) | 별표 · 핵심 / 물음표 · 질문 / 느낌표 · 주의 / 체크 · 확인함 |
| 블록 | 문단·목록 항목 하나 | 여백 세로줄 · 이 단락 전체 |

- **색 다섯**: 노랑 · 주황 · 분홍 · 초록 · 하늘. **이름으로 저장하고 실제 색은 테마가 정한다**(5절).
- **뜻은 사용자가 바꿀 수 있고, 에이전트에게도 간다**(8절). 사람에게 물결 밑줄은 "의심스럽다"지만
  에이전트에게는 그냥 `wavy` 다 — 범례가 그 간극을 메운다. 표시가 곧 지시가 된다.
- `style`·`color` 는 **열거값만** 받는다. 임의 CSS·좌표는 저장하지 않는다(테마 값을 hex·열거값으로
  좁힌 것과 같은 방어).

### 4. 그리기는 **SVG 층 하나**, 질감은 그 위의 스위치다

- 미리보기 iframe 문서 안에 SVG 층 둘을 주입한다 — **형광펜·세로줄은 글자 밑**, **색연필(밑줄·물결·
  취소선·동그라미·점 표시)은 글자 위**. 그래서 다크 테마에서도 글자가 묻히지 않는다.
- 위치는 렌더마다 `Range.getClientRects()` 로 **다시 계산**한다(`ResizeObserver`·폰트 로드·테마 전환).
  저장된 것이 글자 범위라 리플로우가 일어나도 따라간다 — 시안에서 폭을 바꿔 확인할 수 있다.
- 질감(형광펜의 들쭉날쭉한 가장자리·가로 결, 색연필의 종이 결)은 **SVG 필터(`feTurbulence`)** —
  자산 0바이트, 오프라인. 손떨림은 표시 id 를 시드로 한 난수라 **같은 표시는 언제 그려도 같다**.
- **질감은 기본 켜짐, 느리면 끈다.** 끈 모드도 *같은 SVG 경로에서 필터만 뺀다*. CSS Custom Highlight
  API 는 단색 배경밖에 못 칠해 질감을 못 내고, 경로를 둘 두면 모양이 미묘하게 갈린다. 끄는 기준은
  감이 아니라 **성능 예산 실측**(표시 수·문서 길이·재그리기 ms)으로 정하고, 설정에서도 끌 수 있다.
- 주입하는 SVG 는 앱이 만든 정적 마크업이다(스크립트 없음 — `allow-scripts` 미포함 원칙 유지).
  **인용문·메모 텍스트는 iframe 에 들어가지 않는다** — 메모 UI 는 부모(React)에 있다.

### 5. 색은 테마 토큰이다

- 공개 토큰에 `--mark-<color>-ink`(형광펜)·`--mark-<color>-lead`(색연필) 10개를 더한다. prose 토큰처럼
  **기본값은 5토큰에서 파생**되어 테마가 한 항목도 안 적어도 동작한다.
- **대비 하한을 테스트로 지킨다** — 테마·색마다 형광펜 위 본문 4.5:1 이상. 다크의 주황·분홍이 가장
  위험하다.
- **전자잉크 테마**는 다섯 색을 회색 농도로 떨어뜨린다. 뜻은 펜 *모양*이 전한다 — 펜 세트를 모양으로
  가른 이유이기도 하다.

### 6. 스냅샷 기록에 고칠 곳 넷

기존 기록은 "덮이기 직전의 옛 내용"만 뜬다. 표시는 *지금* 판이 필요하다.

1. **표시를 다는 순간 지금 판을 뜬다.** 나중에 재색인이 같은 판을 덮기 직전에 또 뜨려 하면
   `UNIQUE(real_path, mtime)` 가 건너뛴다 — 두 경로가 그대로 맞물린다.
2. **합치기 창(60초)을 무시한다** — 되돌리기 직전 스냅샷과 같은 예외. 여기서 못 뜨면 표시의 바탕이 없다.
3. **표시가 참조하는 판은 정리(문서당 30 · 전체 2,000)에서 뺀다.** 안 하면 바쁜 문서에서 바탕 판이
   *조용히* 지워진다 — 이 설계에서 가장 중요한 한 줄이다. 참조가 0 이 되면 다시 일반 정리 대상이다.
4. **색인 대상이 아니어도 뜬다** — 기록은 워크스페이스 안쪽 색인 대상만 다루지만, 표시는 파일 연결로
   연 낱개 문서에도 달 수 있어야 한다. 고정용 스냅샷은 디스크에서 직접 읽는다(앱 저장 경로와 같다).

그리고 **저장 안 한 편집이 있으면 표시를 막는다** — 미리보기는 편집 중인 버퍼를 그리는데 스냅샷은
저장된 것만 안다. 되돌리기와 같은 규칙이다. 1MB 를 넘는 문서는 스냅샷 상한에 걸리므로 표시도 못 단다
(안내만 한다).

### 7. 메모는 기본 접힘 — 머무르면 툴팁, 펼치면 레일

- **접힘(기본)**: 오른쪽 레일 없음. 메모가 달린 표시 끝에 손글씨 번호(①②)만 남는다. 표시나 번호 위에
  **450ms 머무르면 툴팁 카드** — 그 표시만 남고 나머지는 흐려진다. 툴팁으로 마우스를 옮기는 동안은
  닫히지 않아 [해결됨]·[그 판 보기]를 툴팁 안에서 누른다. 메모가 없어도 **바뀜**이면 툴팁이 뜬다.
- 종이 오른쪽 위 **요약 알약** `메모 3 · 바뀜 1 · 위치 잃음 1 ›` — 누르면 펼친다. 사라진 표시는 걸
  자리가 없어 여기서만 보인다.
- **펼침**: 레일이 표시 높이에 맞춰 늘 보인다. 펼침 여부는 리딩 모드처럼 **영속**한다.
- **폭이 모자라면 펼쳐도 툴팁으로 돌아간다** — 리딩 분할·좁은 창에는 300px 레일이 안 들어간다. 툴바
  접기처럼 중단점이 아니라 **실제 폭을 재서** 정한다.
- **호버만으로는 안 된다** — 번호는 포커스 가능(Enter 로 열림), 펜·터치는 탭, 명령 팔레트에 "메모 목록".

### 8. 브리지: 읽기 도구 하나 — `list_annotations`

```
list_annotations(path) → [{ kind, style, meaning, color, quote, note, state, line, resolved, version_mtime }]
```

- `meaning` 이 핵심이다 — 에이전트는 "물결 친 곳의 근거를 보강하고, 취소선 친 곳은 지워라"를 따로
  지시받지 않아도 안다. `state`·`line` 으로 **자기 수정이 지적된 자리에 닿았는지** 스스로 확인한다.
- ADR 0002 의 원칙 "**파일시스템으로 얻을 수 없는, 이 앱만 아는 것**"에 정확히 들어맞는다. 사람의 주의가
  어디 머물렀는지는 디스크 어디에도 없다.
- **스코프는 기존 읽기 도구와 같다**(`scope.rs`) — 판정이 두 벌이 되면 한쪽만 샌다.
- 에이전트가 표시를 [해결됨]으로 닫는 쓰기 도구는 이번 범위가 아니다. 연다면 제어 도구처럼 **기본 꺼짐**.
- 브리지 없는 사용자를 위해 **[리뷰 요약 복사]** — 칠한 문장 + 뜻 + 메모를 마크다운 목록으로 클립보드에.
  채팅창에 붙여 넣으면 같은 리뷰 고리가 돈다.

### 9. 내보내기 — 대상마다 다르게, 기본 꺼짐

내보내기 대화상자에 **[표시 포함] [메모 포함]**(기본 꺼짐, 마지막 선택 기억). 남에게 보내는 문서에 내
메모가 실수로 섞여 나가면 안 된다. 화면의 접힘/펼침과는 무관하다.

| 대상 | 방식 | 이유 |
|---|---|---|
| PDF | 화면과 같은 SVG(질감 포함)를 **구워 넣는다** | 인쇄는 쪽 폭이 고정이라 좌표 문제가 없다. 지금 PDF 경로가 숨김 iframe 에 렌더 → `print()` 이므로 그 iframe 에서 그린 뒤 인쇄한다 |
| HTML | 글자를 감싸는 **CSS 표시**(`<mark>`·`text-decoration: wavy` 등) | 받는 사람이 창을 바꾸면 구운 SVG 는 어긋난다. 재계산 스크립트는 자기완결·무스크립트 원칙과 맞바꿀 가치가 없다. 한 번 만들고 끝나는 문서라 DOM 을 감싸도 된다 |
| 메모 | 두 형식 모두 본문 끝 번호 절 | 화면의 ①② 와 이어진다 |
| 원본 `.md` | **넣지 않는다** | 파일은 그대로 — 앱의 원칙 |

상태별: 그대로·옮겨짐은 포함 · 바뀜은 지금 판에 표시하고 메모 절에 "원래 문장이 수정됨" · 해결됨·사라짐은
기본 제외.

## 가장 어려운 곳 — 렌더 글자 ↔ 소스 글자

사용자는 **렌더된 미리보기**에서 글자를 고르지만, 스냅샷과 diff 는 **마크다운 소스**다. `**굵게**` 의
별표, 링크 문법, 이스케이프가 그 사이에 있다. 그래서 앵커를 이중으로 둔다.

- **소스 범위**(스냅샷 원문 기준 `src_start`/`src_end`) — 진실원. diff 로 지금 판에 옮긴다.
- **렌더 인용**(`quote` + 앞뒤 문맥 `prefix`/`suffix`, W3C Web Annotation 의 TextQuote 방식) — 옮긴 소스
  범위가 속한 블록(`data-line`)의 렌더 텍스트 안에서 실제 Range 를 찾는다.
- 선택 → 소스 범위: 선택이 걸친 블록의 `data-line` 으로 소스 줄을 좁히고, 그 줄들 안에서 인용을 찾는다.
- **mermaid SVG·KaTeX 수식·코드 블록 안쪽은 범위 펜을 막는다** — 블록 단위(점·세로줄)만 허용. 렌더 글자와
  소스 글자의 대응이 성립하지 않는 곳이다.
- 이 대응·diff 매핑·상태 판정은 **전부 순수 함수**다 → vitest 로 촘촘히 지킨다. diff 는 줄 단위 Myers +
  바뀐 줄 안 글자 단위 정도면 충분해 **직접 짠다**(라이브러리 = 새 의존성 = 확인 게이트, 이득이 없다).

## 저장 — 마이그레이션 v4

```
annotation(
  id TEXT PRIMARY KEY,             -- uuid
  real_path TEXT NOT NULL,
  snapshot_id INTEGER NOT NULL REFERENCES doc_snapshot(id),
  kind TEXT NOT NULL,              -- range | point | block
  style TEXT NOT NULL,             -- 열거값
  color TEXT NOT NULL,             -- yellow | orange | pink | green | blue
  src_start INTEGER NOT NULL, src_end INTEGER NOT NULL,
  quote TEXT NOT NULL, prefix TEXT NOT NULL, suffix TEXT NOT NULL,
  note TEXT,
  resolved INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
)
```

펜의 뜻(사용자 범례)은 `settings` 테이블 — MCP 서버는 별도 프로세스라 localStorage 를 못 읽는다(제어
토글과 같은 이유).

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 미리보기 위 자유 드로잉 캔버스(ShotLog 방식) | 리플로우·문서 변경 모두에서 조용히 어긋난다. **문서에 남는 자유 드로잉은 하지 않는다** — 필요하면 프레젠테이션 모드 한정의 *저장하지 않는* 펜(화면이 고정이라 문제가 없다)으로 따로 |
| 텍스트 인용만으로 재부착(스냅샷 없음) | 바뀌면 "못 찾았다"로 끝난다. 무엇이 어떻게 바뀌었는지를 보여 줄 수 없고, 사라진 표시의 원래 맥락도 없다 |
| md 파일 안에 주석 문법으로 기록(`==형광==` 등) | 파일은 그대로 둔다는 원칙. 에이전트의 다음 쓰기가 덮어쓰고, 다른 도구에서 문법이 깨진다 |
| 사이드카 파일(`문서.md.annotations.json`) | 에이전트 산출물 폴더를 어지럽히고, 감시기·받은 문서함에 소음이 된다. 나중에 *내보내기* 형식으로는 고려할 수 있다 |
| CSS Custom Highlight API 를 1층으로 | 단색 배경만 — 질감도 동그라미·점 표시도 못 한다. 결국 SVG 층이 필요하고, 두 경로를 둘 이유가 없다 |
| rough.js 등 손그림 라이브러리 | 필요한 도형이 다섯 남짓이라 직접 짜도 짧다. 새 의존성 = 확인 게이트 |

## 한계 (알고 두는 것)

- **이름 바꾸기·이동에 표시가 따라가지 않는다** — `real_path` 기준이라 기록과 같은 한계. 감시기의 이름
  변경 이벤트로 옮기는 것은 후속.
- 편집기(소스 쪽) 표시 · 메모 검색 · 프레젠테이션 모드 표시는 MVP 밖.
- 1MB 초과 문서에는 못 단다.

## 단계

1. ✅ ADR + 시안(이 문서)
2. 앵커 코어 — 렌더↔소스 대응 · diff 매핑 · 상태 판정 (순수 로직 + vitest)
3. 저장 — 마이그레이션 v4 · 스냅샷 고정/정리 예외 (Rust + `cargo test`)
4. 화면 — SVG 층 · 펜 트레이 · 여백 ＋ · 메모 접힘/툴팁/레일 · 테마 토큰 · **`probe:annot` 신설**
   (폭·테마·RTL·분할에서 표시가 글자를 따라가는지 기하로 잰다)
5. 내보내기 · `list_annotations` · [리뷰 요약 복사]

시기는 **1.0 위생 뒤, 1.1 후보**다. 1.0 헤드라인(에이전트 브리지)을 흐리지 않는다. 무료로 나간 적이 없는
기능이라 1.1 유료화(Pro) 범위의 후보이기도 하지만, 그 결정은 열어 둔다.
