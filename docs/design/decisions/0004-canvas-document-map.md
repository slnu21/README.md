# ADR 0004 — 캔버스: JSON Canvas 위의 "문서 지도"

- 상태: 채택(Accepted) — 구현 전 설계
- 날짜: 2026-10-10
- 시안: [mockups/canvas.html](../../mockups/canvas.html)
- 관련: [ADR 0003 — 표시 펜](0003-annotation-pens.md)(캔버스 펜과 경계를 나눈다)

## 맥락

사용자 제안: 지금 있는 md 파일들을 거대한 캔버스에 자유롭게 배치하고, 연결선과 드로잉을 더해 원하는
연결 구조를 만들고 싶다(옵시디언 Canvas 류).

이 앱에는 이미 "**파일은 그대로, 배치는 내 마음대로**"라는 원칙이 있다 — 가상 폴더는 디스크를 건드리지
않고 파일을 *트리로* 재배치한다. 캔버스는 같은 일을 *평면에* 하는 것이다. 다만 잘못 만들면 앱이
화이트보드나 옵시디언 축소판이 되어 "경량 리더"라는 정체성이 흐려진다.

## 결정

### 1. 포맷은 JSON Canvas 1.0 그대로 — 디스크의 `.canvas` 파일

옵시디언이 공개한 **JSON Canvas**(MIT, <https://jsoncanvas.org/spec/1.0/>)를 독자 확장 없이 따른다.

- `nodes`(text · file · link · group, 모두 `x/y/width/height` + 선택 `color`) · `edges`(`fromNode/toNode`,
  선택 `fromSide/toSide`·`fromEnd/toEnd`·`label`·`color`). 배열 순서가 z 순서다.
- **SQLite 가 아니라 디스크 파일이다.** 그래야 ① 옵시디언과 파일을 그대로 주고받고 ② **에이전트가 fs 로
  쓸 수 있고** ③ 받은 문서함·문서 기록·감시기가 다른 문서와 똑같이 다룬다.
- **모르는 필드는 보존한다** — 읽을 때 노드·선·최상위의 알 수 없는 키를 들고 있다가 저장할 때 그대로
  쓴다. 다른 앱(또는 미래의 명세)이 넣은 것을 우리가 지우면 안 된다. 왕복 테스트로 지킨다.
- 색 프리셋 `"1"`~`"6"` 의 실제 색은 명세가 일부러 비워 두었다 → **테마 토큰** `--canvas-c1..6` 으로 칠한다
  (hex 값은 그대로 존중).

### 2. 정체성: 화이트보드가 아니라 **문서 지도**

- **file 노드가 주인공**이다. 카드는 읽으러 가는 길이지 그 자리에서 다 읽는 곳이 아니다 —
  **더블클릭 = 탭으로 열기**(`subpath` 가 `#헤딩`이면 그 위치로).
- 도형 라이브러리 · 스티커 · 정렬/배분 도구 · 레이아웃 자동 정리는 넣지 않는다.

### 3. 카드는 두 단계까지만 — 본문 렌더는 하지 않는다

| 확대 | 카드에 보이는 것 |
|---|---|
| 72% 미만 | **제목만** — 확대율에 반비례하는 글자 크기로 멀리서도 읽힌다 · 받은 문서함 배지 |
| 72% 이상 | **아웃라인 + 첫 문단** · 경로 · 배지 |

- **mermaid·수식·코드 하이라이트를 카드에서 렌더하지 않는다**(사용자 결정). 카드 수백 장에서 미리보기
  iframe 을 띄우는 것은 성능상 성립하지 않고, 그 역할은 탭이 이미 한다.
- 아웃라인·첫 문단은 **색인에서** 온다(`file_index.content`) — 파일을 매번 읽지 않는다. 헤딩 파싱은 MCP
  `outline` 이 쓰는 Rust 파서(펜스·frontmatter·BOM 처리 포함)를 재사용한다. 판정이 두 벌이 되면 한쪽이
  어긋난다.
- **참조한 파일이 없으면 카드를 지우지 않고 "파일 없음"으로 보여 준다** — 옮겼거나 지운 것을 사용자가
  알아야 한다. 이름 변경 추적(감시기의 rename 이벤트로 참조 갱신)은 후속.

### 4. 연결선 — 고를 수 있고, 옮길 수 있고, 제멋대로 바뀌지 않는다

- 카드 네 변의 연결점에서 끌어 시작한다. 끄는 동안 **가장 가까운 카드 변의 연결점에 달라붙고**(카드 밖
  28px 까지) 그 점을 강조한다. 놓으면 양 끝의 변이 모두 저장된다.
- 선을 누르면 **양 끝에 손잡이** → 끌어서 다른 연결점·카드로 옮긴다. 선택 막대에 색 6 · 라벨 · 방향
  뒤집기 · 지우기.
- **끝점을 옮길 때 반대쪽 끝의 변을 그 자리에 고정해 저장한다.** 변 없이 저장된 선(옵시디언이 그렇게
  만들 수 있다)은 자동 계산되는데, 한쪽을 옮기면 그 계산이 *반대쪽 출발 변까지* 바꿔 버린다 — 시안에서
  사용자가 "출발지가 제멋대로 바뀐다"로 짚었다.

### 5. 렌더링 — 직접 구현, 층 순서가 곧 동작

- DOM 카드 + SVG 연결선 + CSS `transform` 이동·확대. 노드·선·그룹·펜이면 범위가 감당할 만하다 —
  **의존성 0**. 막히면 React Flow(xyflow, MIT)가 대안이지만 새 의존성 = 확인 게이트.
- **층: 그룹 상자 → 연결선 → 카드 → 라벨 → 드로잉 → 선 끝 손잡이.** 파일의 배열 순서와 별개로 화면에서
  그룹을 늘 맨 아래에 둔다(파일 순서는 건드리지 않는다).
  - 선이 그룹 밑에 깔리면 그룹 안의 선을 누를 수 없다(사용자 지적 — 카드를 그룹 밖으로 빼야 지울 수 있었다).
  - **선 끝 손잡이는 카드 연결점과 같은 자리에 있다** — 손잡이가 카드보다 아래면 손잡이를 잡은 줄 알았는데
    카드 연결점이 잡혀 *새 선이 생긴다*(시안에서 실제로 났다: 선 5 → 6). 그래서 맨 위.
  - 겹치는 조작 대상은 **캡처가 아니라 히트 테스트(`elementFromPoint`)로** 지킨다 — 시안의 `#relink`
    자가 점검이 그 모양이다(고치기 전 `span.h` · 선 5→6 / 고친 후 `circle.knob` · 5→5).

### 6. 드로잉(3단계) — 카드 *사이와 주변*에만

- 캔버스는 좌표 자체가 콘텐츠라 **자유 드로잉이 어긋나지 않는다**(ADR 0003 이 리플로우 문서 위 드로잉을
  기각한 이유가 여기엔 없다). 펜 트레이·질감·색 5는 표시 펜과 같은 것을 쓴다 — 두 기능이 한 가족으로 보인다.
- **그러나 카드 안 글자 위에 그은 선은 어긋난다** — 카드 상자는 고정이지만 *안의 글자 배치는 확대 단계마다
  바뀐다*(시안에서 글 상자 한 줄에 그은 형광펜이 단계가 바뀌자 떠 있었다). 그래서 경계를 나눈다:
  - **캔버스 펜** = 카드 사이·주변(묶기 · 화살표 · 강조). 카드 바깥을 감싸는 고리는 어느 단계에서도 맞다.
  - **카드 안 글자 표시** = **표시 펜(ADR 0003)** 의 일. 문서에 묶이므로 캔버스에서든 탭에서든 같은 자리다.
- 저장: 확장 필드 **`x-readme-ink`**(`{version, strokes:[{id, kind: pencil|marker, color, points}]}`).
  **옵시디언이 모르는 최상위 필드를 저장할 때 보존하는지는 미확인** — 3단계의 첫 실측 항목이다. 지운다면
  옆 파일 `<이름>.canvas.ink` 로 뺀다(옵시디언에서 한 번 저장했다고 드로잉이 사라지면 안 된다).

### 7. 이미 있는 것과 잇는다

| 기능 | 캔버스에서 |
|---|---|
| 받은 문서함 | 바뀐/새 문서 카드에 배지. **`.canvas` 파일 자체도 받은 문서함 대상** — 에이전트가 쓴 지도가 아침에 뜬다 |
| 검색 | `.canvas` 를 색인 대상에 넣고 **text 노드의 글**을 색인한다(JSON 그대로가 아니라) |
| 문서 기록 | `.canvas` 도 스냅샷 대상 — 배치를 망쳐도 되돌린다 |
| 워크스페이스 | 트리에 `.canvas` 표시 · 트리에서 끌어 놓으면 file 노드 · 원본은 그대로 |
| 링크 열기 | link 노드는 미리보기를 가져오지 않는다(오프라인). 누르면 기존 링크 열기 정책(`open_url`) |

### 8. 에이전트: 새 도구 없이 — "지도를 남겨 달라"

`.canvas` 는 그냥 JSON 이라 에이전트가 fs 로 쓴다. ADR 0002 의 원칙("파일시스템이 하는 일은 도구로 주지
않는다")대로 **MCP 도구를 늘리지 않는다**. 권장 사용법으로 문서화한다: 밤새 보고서 열 개를 쓴 에이전트가
**그 관계도까지 `.canvas` 로 남기면**, 사람은 받은 문서함에서 지도부터 연다. `open_in_app` 이 `.canvas` 를
열 수 있으면 충분하다.

### 9. 보안 — 캔버스는 남이 쓴 파일이다

에이전트·다른 앱이 쓴 `.canvas` 의 text 노드는 **신뢰할 수 없는 마크다운**이고, 카드는 미리보기 iframe 이
아니라 **앱 DOM** 에 그려진다. 그래서 text 노드는 markdown-it `html: false` + DOMPurify 정화를 거치고,
이미지는 CSP 가 이미 원격을 막는다. file 노드 경로는 열기 전에 기존 파일 열기 경로(Rust 커맨드)를 그대로 탄다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| SQLite 에 저장(가상 폴더처럼) | 옵시디언 호환 불가 · 에이전트가 쓸 수 없음 · 받은 문서함·기록과 따로 놀아야 함 |
| 독자 포맷 | 공개 포맷이 이미 있고 요구를 다 덮는다 |
| 카드에 본문 렌더(mermaid·수식) | 카드 수백 장에서 무너진다. 탭이 그 역할을 한다(사용자 결정) |
| Excalidraw | 자기 포맷 · 번들 수 MB · JSON Canvas 와 안 맞음 |
| tldraw | 상업적 사용에 라이선스 필요 — permissive 원칙 위반 |
| React Flow | 쓸 만하지만 직접 구현 범위가 작아 의존성을 들일 이유가 아직 없다(막히면 재검토, 확인 게이트) |
| 카드 안 글자 위 드로잉 허용 | 확대 단계마다 글자 배치가 바뀌어 어긋난다 → 표시 펜의 일 |

## 시안에서 실측한 함정

1. **`transform: scale` 된 world 안에서 overflow 를 가진 *flex 항목*이 있으면 크롬이 노드 묶음을 통째로 안
   그린다**(헤드리스, GPU 켜도 동일 → WebView2 도 같을 공산이 크다). 처음 캡처가 텅 빈 캔버스였고, 변형
   파일로 하나씩 지워 좁혔다. 자르기는 카드(`position:absolute` + `overflow:hidden`)에 맡긴다. 본문 단계를
   없앤 덕에 카드 안 스크롤 영역도 없다. **구현 때 프로브로 지킨다.**
2. 카드 안 글자 위 드로잉의 어긋남(6절).
3. 선 끝 손잡이와 카드 연결점의 층 순서(5절).

## 단계

1. **JSON Canvas 1.0 완전 지원** — 열기·편집·저장, 모르는 필드 보존, **옵시디언 왕복 실측**(옵시디언에서
   만든 파일을 열고 저장한 뒤 옵시디언에서 다시 열기 · 그 반대)
2. **카드 두 단계 + 연동** — 색인 기반 아웃라인 · 파일 없음 상태 · 받은 문서함·검색·기록·트리 · `probe:canvas`
   (층 순서 히트 테스트 · 확대 단계 전환 · 빈 렌더 회귀)
3. **드로잉** — `x-readme-ink` 보존 실측 먼저, 안 되면 옆 파일
4. (별도) `.canvas` 파일 연결 — MSIX 매니페스트 변경이라 그때 확인 게이트

시기는 **1.2 후보** — 1.1 표시 펜 다음이다. 표시 펜이 읽기의 핵심에 더 가깝고 범위가 작으며, 캔버스 드로잉이
표시 펜의 펜 트레이·질감을 재사용한다.
